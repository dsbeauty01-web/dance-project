The 4 permissions — justification + screencast script

pages_show_list

Justification (paste into Meta form):
After the Page owner signs in with Facebook Login, Maya Live calls GET /me/accounts to display the list of Pages they manage, so the owner can choose which Page Maya will host the live broadcast on. We read only Page name and ID. Without this permission the owner cannot select a Page and the product cannot function.
Screencast shot-script:
  1. Open the Maya Live web app; click “Connect Facebook.”
  2. Facebook Login dialog appears; sign in as the test user; approve pages_show_list.
  3. App renders a dropdown of the user’s Pages (data from /me/accounts).
  4. Cursor selects MythicMingle from the list. Hold 2 seconds on the visible list.

pages_read_engagement

Justification (paste into Meta form):
Maya reads viewer comments on the connected Page’s live video via GET /{live-video-id}/comments (polled in reverse-chronological order) so the AI host can answer viewers by name during the stream. This is the core interaction of the product — the host responding to live comments.
Screencast shot-script:
  1. Page is live (from the next permission’s flow). Operator console open beside the live view.
  2. From a second account, post a comment on the live video (e.g. “Hi Maya, where are you from?”).
  3. Within ~2 s the comment appears in Maya’s console (pulled from the comments edge).
  4. Maya speaks a reply that references the comment/commenter. Show the comment → spoken reply linkage on screen.

pages_manage_posts

Justification (paste into Meta form):
Maya creates and ends the live video post on the connected Page on the owner’s behalf (POST /me/live_videos?status=LIVE_NOW to create, POST /{id}?end_live_video=true to end). This publishes and later closes the broadcast the owner authorized.
Screencast shot-script:
  1. In Maya Live, operator clicks “Go Live.” App calls create-live-video and shows the returned RTMPS ingest URL.
  2. Switch to the Page — a live post now appears on MythicMingle.
  3. Operator clicks “End Stream.” App calls end_live_video=true.
  4. Switch to the Page — the live post has ended. Show both create and end.

publish_video

Justification (paste into Meta form):
publish_video authorizes the Live Video API broadcast itself: Maya pushes the AI host’s video to the Page over RTMPS (rtmps://rtmp-api.facebook.com/rtmp/<key>) using the ingest URL returned at creation. Without it the created live video has no video feed.
Screencast shot-script:
  1. Immediately after “Go Live,” the app pushes Maya’s avatar video to the RTMPS secure_stream_url.
  2. On the Page’s live post, Maya’s avatar is visibly streaming and moving/talking.
  3. Hold ~10 s on the public live playing so the reviewer sees a real broadcast.

Your dashboard steps (only you can click these)

A · Create a test user with a Page to review against

  1. developers.facebook.com → My Apps → open Maya Live (App ID 1335138022110608).
  2. Left sidebar → App roles → Test Users → Create test users (set “Authorize test user for this app” = Yes; pick the 4 permissions).
  3. On the new test user’s row → Options → Log in as → this opens Facebook as that user.
  4. As the test user, create a Page (test users can own Pages). Note: test-user Pages have 0 followers, so use them for the flow screencast, but the FINAL public go-live must be on a real Page ≥100 followers with a ≥60-day account.
  5. Back in your real Page MythicMingle → Settings → Page roles → add the reviewer/test identity as Admin if you want them to exercise the real Page.

B · Submit for review

  1. App dashboard → App Review → Permissions and features.
  2. Request Advanced access on each of the 4 scopes above; paste the matching justification.
  3. Upload the screencast that follows the shot-scripts; paste the Privacy Policy URL and test-user login.
  4. Complete Data Use Checkup and Business Verification if prompted, then Submit.
